# Agent Conventions

Shared conventions for AI coding agents working in this repository.
Tool-specific entry points (`CLAUDE.md`, `WARP.md`) point here; keep the rules themselves in this file only.

## Project overview

questionsafe is a Python library and CLI for composing quizzes and exporting them as Moodle XML.
The design goal is an R/exams restricted to Moodle: a narrower target than R/exams, in exchange for
deeper use of Moodle-native features (question bank categories, tags, idnumbers, cloze, per-type options).

Key internal documents:

- `docs/api-overview.md` — one-file map of the package and its public API
- `docs/references.md` — official Moodle XML sources; consult these instead of guessing XML elements
- `docs/roadmap.md` — planned features and known cleanup items

## General rules

- Codebase optimization is prioritized over backward compatibility.
  Never introduce code just for backward compat; delete old code and rewrite tests and docs.
  Optimization includes clarity and conciseness.
- Write the most idiomatic Python, as an experienced developer would.
- When introducing a new feature, write a failing test first, then implement (TDD).

## Running things

Run all Python scripts and third-party programs through the uv runner:

- `uv run pytest` (not `pytest`)
- `uv run path/to/script.py` (not `python path/to/script.py`)
- `uv run ruff check`
- `uv run quarto render`

## Naming conventions

For user-facing objects, give IDE-friendly names with a common prefix:

- `set_*` methods update an attribute (overwrite).
- `add_*` methods append one item to a list-type attribute.

## Documentation

- Main documentation lives in `docs/`; render with `quarto` and `quartodoc`.
- `README.md` is generated by `quarto render README.qmd`. Never edit `README.md` by hand.

## API design philosophy

- Favor clarity and consistency over backward compatibility.
  Remove redundant or legacy APIs quickly and update tests and docs
  (e.g., `Cloze.encode` was removed in favor of the instance method `.cloze()`).
- Provide two tiers of APIs:
  - "Safe" methods that are validation-proof and guard against non-typical usage.
  - Low-level setters and adders for advanced scenarios; these may require manual validation awareness.

## Safe API contract

- Safe methods are tagged with the decorator `base._safe.safe_api` and their docstrings are
  prefixed with `[SAFE]` for IDE visibility.
- Introspection helper: `questionsafe.list_safe_apis` (also at `questionsafe.base.list_safe_apis`).
- Principle: after any chain of safe calls, `validate()` passes without further changes.

Current safe methods:

- `MultiChoice`: `set_choices_correct`, `set_choices_wrong` (fraction must be in the allowed set),
  `add_choice_correct` (recalculates a uniform distribution and snaps to allowed fractions),
  `add_choice_wrong` (guards the fraction to the allowed set),
  `set_scoring` (sets every wrong choice by a named R/exams rule, snapped to the allowed set;
  also on `SingleChoice`)
- `SingleChoice`: `set_choice_correct` (overwrites to exactly one correct=100 and removes a
  conflicting wrong duplicate), `add_choice_correct` (raises if a correct answer already exists)
- `TrueFalse`: `set_correct_if_true`, `set_correct_if_false`.
  `set_choice_correct`/`set_choice_wrong` are not safe because they accept arbitrary text.

## Validation rules (selected)

- `MultiChoice`
  - Positive fractions must sum to 100.
  - Fractions must come from Moodle's allowed set (including negatives).
  - `add_choice_correct` under the safe contract: the first correct gets 100; if existing corrects
    are uniform and sum to 100, recompute uniform = 100/(n+1) and snap to an allowed value;
    if snapping is impossible (e.g., 100/11) or the corrects are not uniform, raise and suggest `set_answers`.
- `SingleChoice`: exactly one correct answer with fraction=100 and no other positive fractions.
- `TrueFalse`: exactly two answers with texts "true" and "false" (case-insensitive).

## Answer API consistency

- `ShortAnswer.add_answer` defaults to fraction = 100.0.
- `Numerical.add_answer` uses the parameter name `answer` and accepts
  `NumericalAnswer | float | int` (`NumericalAnswerLike`).

## Cloze embedding

- Prefer calling `.cloze()` on question instances (`SingleChoice`, `MultiChoice`, `ShortAnswer`, `Numerical`).
- The orientation parameter is typed `Optional[Literal["v", "h"]]` and documented per type.
- The precheck validates weights and content; numerical answers are excluded from non-empty-text checks.

## Utilities

- `base._constraints.uniform_fraction(n)` returns 100.0/n for n > 0.
- `base._constraints.snap_allowed_positive(value, tol=1e-4)` snaps to a canonical allowed positive
  fraction or returns `None`.
